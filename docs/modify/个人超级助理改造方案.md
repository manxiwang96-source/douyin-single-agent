# 个人超级助理改造方案

> 本文档是当前已锁定的改造套餐，供后续实现直接执行。标识符、环境变量、接口路径保持英文。密钥只写本地 `.env`，不入库、不写本文档。
>
> langgraph.com.cn 链接只作框架对照，禁止把文档示例整段复制进仓库。

## 1. 摘要

在现有小红书运营机器人 MVP 上改造成**个人超级助理**。图拓扑保持 `START -> chatbot -> tools_condition -> tools -> chatbot`，节点仍只有 `chatbot` 和 `tools`。不新增节点、不做 Supervisor、不拆独立小红书运营角色。

产品身份是个人超级助理。小红书写稿、配图、配视频是同一助手的能力：只有用户明确要求时才 `search_kb` 并输出【标题】【正文】【标签】。未点名小红书时，用自然语言回答，禁止套笔记格式、禁止搜 KB。

v1 必须立刻跑通，不等 08:00：

- 真实调用仓库内 FastMCP，返回今天星期几、广州天气和温度。
- 由同一张图里的模型根据事实生成 2–4 条情境建议（下雨带伞、工作日上班只是例子，禁止 if-else 写死）。
- 真实发出一封 163 邮件。Mock pytest 单独全绿不算交付。

历史 `docs/小红书运营机器人MVP方案.md` 与 `docs/summary/` 复盘文档保持原样，作为 MVP 基线，不改写。

## 2. 已锁定决策

| 主题 | 选择 |
| --- | --- |
| 产品身份 | 个人超级助理；小红书是能力，不是独立角色 |
| 图拓扑 | 保持现有 `chatbot` + `tools`；HITL 仍在 `generate_image` / `generate_video` 内部 `interrupt()` |
| UI | Streamlit 仍是薄 HTTP 客户端；标题改为「个人超级助理」 |
| 主动触达 | SMTP 邮件，不用 Streamlit 弹窗 |
| 邮箱 | 网易 163，`SMTP_SSL smtp.163.com:465` |
| MCP | 仓库内 FastMCP stdio；`langchain-mcp-adapters` 的 `MultiServerMCPClient.get_tools()` 并入现有 tools |
| 天气 | Open-Meteo，无 API key；默认城市广州，可用 `ASSISTANT_CITY` 覆盖 |
| 晨报 | 每天 08:00 Asia/Shanghai；MCP 取事实 + 同一图 `ainvoke` 写建议 + `send_email` |
| 喝水 | 08:00–22:00 每 2 小时；08:00 并入晨报，其余 10/12/14/16/18/20/22；模板邮件，不走 LLM |
| 记忆 | `PostgresSaver` 替换 SQLite checkpoint；`PostgresStore` 存跨线程 profile/jobs；KB RAG 仍用 `InMemoryStore` |

| 调度 | FastAPI lifespan 里 APScheduler；OSS 无 LangGraph Platform Cron |
| 验收 | 默认 pytest 全 mock；`RUN_LIVE_ASSISTANT=1` 立即跑晨报，真实 MCP + 真实 163 邮件 |

明确不做：

- `create_react_agent`
- 多智能体 Supervisor / 独立小红书 Agent
- 把 MCP 文档的 streamable-http 天气示例当生产传输
- LangGraph Platform Cron / 自定义路由
- 小红书登录或发布
- 生产 Postgres 挂了静默回 SQLite
- 把密钥写入 git 或 memory-bank

## 3. 产品身份与提示词

`SYSTEM_PROMPT` 改写为人设「个人超级助理」，禁止「你是小红书运营助手」口吻。

行为分流：

- 日常问答、天气、提醒、记忆：自然语言。
- 用户明确要求写小红书笔记：先 `search_kb`，再【标题】【正文】【标签】。
- 用户明确要求配图：`generate_image`（默认 3:4，生成前 HITL）。
- 用户明确要求视频：`generate_video`（默认 9:16，生成前 HITL）。
- 未要求时禁止套笔记格式、禁止搜 KB、禁止声称已登录/已发布小红书。

界面：

- Streamlit `st.title("个人超级助理")`，`page_title` 同步。
- 副标题提示：可写小红书笔记、配图/视频、晨间简报与喝水提醒。
- FastAPI title 同步为个人超级助理，不再用 `Xiaohongshu Ops MVP`。

## 4. 保持不变

- Graph 节点只有 `chatbot`、`tools`。
- 媒体 HITL：`interrupt()` 在工具内，审核卡 Approve / Skip。
- 媒体只写 `outputs/images`、`outputs/videos`。
- 现有工具 `search_kb`、`generate_image`、`generate_video` 保留。
- Demo KB 仍是 `knowledge/*.md` → `InMemoryStore` + `BAAI/bge-m3`。
- 现有 FastAPI 线程合同保留：`/health`、`/v1/config`、`/v1/threads*`、`/v1/media/*`。
- 默认 pytest 全 mock；现有 `RUN_LIVE_API=1` 小红书 cheapest 冒烟保留。
- 历史 MVP / 复盘文档及其结构测试不改。

## 5. 记忆改造

对照记忆分层：checkpointer = 线程内短期记忆；store = 跨线程长期记忆。

生产：

- `PostgresSaver` 替换 `SqliteSaver`（`data/checkpoints.sqlite`）。
- `PostgresStore` 存跨线程事实、profile、任务幂等记录。
- 首次 `setup()`，然后 `compile(checkpointer=..., store=...)`。
- 连接串只来自 `POSTGRES_URI`。库不存在则创建。Postgres 不可用则启动失败。

测试：

- 继续 `InMemorySaver`。
- 不连真实 Postgres。

KB：

- RAG 仍用进程内 `InMemoryStore`，不用 pgvector。

幂等：

- namespace `("assistant", "jobs")` 记录晨报/喝水是否已跑，避免重复发信。

## 6. MCP 与天气

自建 `mcp_servers/personal.py`：FastMCP + `@mcp.tool()` + `mcp.run(transport="stdio")`。

工具至少包括：

- 当前日期时间与星期几（Asia/Shanghai）。
- 指定城市天气与温度（默认广州，Open-Meteo，无 API key）。

接线：

- `MultiServerMCPClient` stdio 加载该服务器。
- `await client.get_tools()` 并入现有 `build_tools()` 列表，交给现有 `ToolNode` 与 `bind_tools`。
- FastAPI message/resume 改 `ainvoke`，因为 MCP 工具是异步的。
- 不另起一套 agent，不复制文档里的天气 HTTP demo。

## 7. 邮件、晨报与喝水

`send_email` 作为普通工具加入同一 `tools` 节点。

SMTP（只写本地 `.env`）：

- `SMTP_HOST=smtp.163.com`
- `SMTP_PORT=465`
- `SMTP_SSL=true`
- `SMTP_USER` / `SMTP_FROM` / `SMTP_TO` 默认同一 163 邮箱
- `SMTP_PASSWORD` 为授权码，禁止写入本文档和 git

晨间简报（hybrid）：

1. 调度或手动 job 先确定性调用 MCP，拿到星期几、天气、温度。
2. `ainvoke` 同一张图，让模型根据事实写 2–4 条情境建议，并调用 `send_email`。
3. 模型未发信则 fallback 仍把事实发到邮箱，保证交付。
4. 建议必须由模型生成；下雨带伞、工作日上班只是例子。

喝水提醒：

- 窗口 08:00–22:00，每 2 小时一次。
- 08:00 喝水并入晨报，不单独再发一封。
- 10/12/14/16/18/20/22 用模板邮件，不走 LLM。

立刻验收，不读时钟：

- `run_morning_brief()`
- `run_hydrate(slot)`
- `POST /v1/assistant/jobs/run`，body `kind=morning_brief|hydrate`

生产调度：

- FastAPI lifespan 注册 APScheduler。
- 测试 `scheduler_enabled=False`。
- 启动补跑：现在 ≥ 08:00 补一次晨报；喝水只补当前槽；22:00 后不补。
- 幂等写入 `PostgresStore` namespace `("assistant", "jobs")`。

## 8. 配置

实现时扩展 `.env.example`，不覆盖用户现有密钥。新增项示例（值为占位，真实密钥只在本地 `.env`）：

```
POSTGRES_URI=postgresql://postgres@127.0.0.1:5432/agentdemo
ASSISTANT_CITY=广州
ASSISTANT_TIMEZONE=Asia/Shanghai
SCHEDULER_ENABLED=true
SMTP_HOST=smtp.163.com
SMTP_PORT=465
SMTP_SSL=true
SMTP_USER=
SMTP_PASSWORD=
SMTP_FROM=
SMTP_TO=
```

规则：

- `POSTGRES_URI` 含密码时只出现在本地 `.env`。
- 生产缺 SMTP / Postgres 配置则启动失败。
- 测试通过 Settings 注入，不读真实邮箱授权码。

依赖补齐（写入 `requirements.txt`）：`langchain-mcp-adapters`、`mcp`、`psycopg[binary,pool]`、`langgraph-checkpoint-postgres`、`apscheduler`。venv 已有前两者时也要写进 requirements，避免环境漂移。

## 10. 实现顺序

后续编码按此顺序，一步一测一中文 commit：

1. 先改 `memory-bank/design-document.md`、`tech-stack.md`、`implementation-plan.md`，写入对照链接和「只参考、不整段复制」。
2. Settings + `.env.example`：Postgres、SMTP、城市、时区、调度开关。
3. `PostgresSaver` + `PostgresStore` + 记忆工具；测试仍 `InMemorySaver`。
4. FastMCP datetime/weather，并入现有 tools，不改图节点。
5. `send_email` + `run_morning_brief()` / `run_hydrate(slot)` + `POST /v1/assistant/jobs/run`。
6. 生产 APScheduler；测试关闭调度。
7. FastAPI message/resume 改 `ainvoke`；改写 `SYSTEM_PROMPT` 与 Streamlit 标题。
8. mock pytest 全绿后，跑 `RUN_LIVE_ASSISTANT=1 tests/test_live_assistant.py`：立即晨报，真实 MCP + 真实 163 邮件。
9. 里程碑后更新 `memory-bank/architecture.md` 与 `agent_memory/*`。
