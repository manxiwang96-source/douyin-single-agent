## 1. 一句话结论

**人话：** 这已经不是「小红书写稿机器人」了，而是一个住在你电脑里的个人超级助理：能聊天、记事、看广州天气、早发晨报、按时催喝水；只有你点名要小红书时，它才去翻知识库并按笔记格式写。
举个例子：你在 Streamlit 里问「今天星期几」，它会调仓库里的 FastMCP 工具回答；每天 08:00 它会自己取星期几/天气/温度，让同一张图写 2-4 条建议，再发到 `SMTP_TO` 配置的 163 邮箱。你没有点名小红书时，它不会突然甩出【标题】【正文】【标签】。

**实现要点：**

- 产品身份在 `app/prompts.py` 的 `SYSTEM_PROMPT`：你是个人超级助理，不是小红书运营助手。
- 运行时仍是双进程：FastAPI 持有 Graph，Streamlit 只是薄 HTTP 客户端，标题是「个人超级助理」。
- 图拓扑没变：`START -> chatbot -> tools_condition -> tools -> chatbot`，节点只有 `chatbot` 和 `tools`。
- 生产记忆是 `PostgresSaver` + `PostgresStore`；测试仍 `InMemorySaver`；知识库 RAG 仍进程内 `InMemoryStore`。
- 仓库内 FastMCP stdio（星期几 + 广州天气温度）经 `MultiServerMCPClient.get_tools()` 并入现有 `ToolNode`。
- 主动触达是 163 SMTP，不是页面弹窗。交付门禁是 `RUN_LIVE_ASSISTANT=1` 立即跑晨报：真实 MCP + 真实发信。代码基线 `275d208` 时，live 晨报曾落到 `status=sent`。

**对照文档：** [构建基础聊天机器人](https://langgraph.com.cn/tutorials/get-started/1-build-basic-chatbot/index.html)、[智能体架构概念](https://langgraph.com.cn/concepts/agentic_concepts.1.html)

## 3. 产品边界

**人话：** 它愿意帮你做日常事，也愿意在你点名时写小红书；但它不会登录小红书，也不会自己发明一套多智能体班底。

### 3.1 做了什么

**人话：** 日常问答走自然语言；点名小红书才检索；点名配图/视频才审核后生成；到点发邮件。

| 能力 | 实际行为 | 例子 |
| --- | --- | --- |
| 日常对话 | 天气、星期几、提醒、记忆、邮件，用自然语言 | 「今天星期几」「记住我周一要交周报」 |
| 小红书写稿 | 用户明确要求时才 `search_kb`，再输出【标题】【正文】【标签】 | 「帮我写一条敏感肌精华的小红书笔记」 |
| 廉价生图 | Gateway `POST /images/generations`，默认 `quality=low` + `1024x1536` | 「给这款精华做一张 3:4 封面」 |
| 廉价生视频 | DashScope 异步合成 + poll，默认 2s + `480P` + `9:16` | 「做一条 9:16 短视频」 |
| 人工审核 | 只在生图/生视频工具内部 `interrupt()` | 审核卡 Approve 才调媒体 API，Skip 不调 |
| 晨间简报 | MCP 取事实 → 同一张图写建议 → `send_email` | 08:00 或手动 `POST /v1/assistant/jobs/run` |
| 喝水提醒 | 10/12/14/16/18/20/22 模板邮件，不走 LLM；08:00 并入晨报 | 主题「喝水提醒」 |
| 跨会话记忆 | `remember_fact` / `recall_facts` 写入/读取长期 store | 「记住我对花生过敏」 |
### 3.2 明确不做

**人话：** 不是什么智能体教程里有的东西，本仓库都要搬进来。下面这些是有意关掉的。

- 不新增图节点，不做 Supervisor，不用 `create_react_agent`。
- 不登录、不发布、不投放小红书。
- 不接 Tavily / 外网检索；知识库仍是本地 `knowledge/*.md`。
- 不用 LangGraph Platform Cron；OSS 没有那套云调度，本仓库用 APScheduler。
- 不用 MCP 文档里的 streamable-http 天气示例当生产传输，本仓库是 FastMCP **stdio**。
- 生产 Postgres 挂了不会静默回 SQLite。
- 不做时间旅行产品化，不做流式输出（仍是 `ainvoke` 阻塞）。
- 不用 pgvector，不迁移旧的 `data/checkpoints.sqlite`。
- 密钥不入库。

**对照文档：** [多智能体系统概念](https://langgraph.com.cn/concepts/multi_agent.1.html)（对照但不采用 Supervisor）、[MCP](https://langgraph.com.cn/agents/mcp/index.html)（对照但不采用 `create_react_agent` / streamable-http 天气示例）、[FAQ](https://langgraph.com.cn/concepts/faq/index.html)（Platform Cron 属于平台能力，本仓库不用）、[时间旅行](https://langgraph.com.cn/tutorials/get-started/6-time-travel/index.html)（未做）、[流式处理](https://langgraph.com.cn/concepts/streaming.1.html)（未做）

## 4. 进程与模块分层

**人话：** 用户永远只跟网页聊天；真正的脑子在 FastAPI 里。Streamlit 不持有 Graph，所以刷新页面不会把模型、Postgres、MCP 子进程一起带走。

可以把它想成餐厅：Streamlit 是点单柜台，FastAPI 是后厨，Graph 是固定的炒菜流程，工具是刀和锅。

```text
用户
  └─ Streamlit（薄 HTTP 客户端，标题「个人超级助理」）
        └─ FastAPI 合同（ainvoke + jobs）
              └─ AppRuntime
                    ├─ ChatOpenAI（timeout + max_tokens）
                    ├─ StateGraph：chatbot + tools
                    ├─ InMemoryStore（KB RAG，bge-m3 / 测试 hashing）
                    ├─ PostgresSaver + PostgresStore（生产）
                    │     测试改为 InMemorySaver + 内存 store
                    ├─ MCP 工具（stdio FastMCP → ToolNode）
                    ├─ SmtpEmailClient（smtp.163.com:465）
                    ├─ APScheduler（lifespan 里启动）
                    ├─ ImageClient → Gateway
                    └─ VideoClient → DashScope
```
| 层 | 文件 | 职责 |
| --- | --- | --- |
| 配置 | `app/config.py` | env、cheapest 媒体、城市时区、Postgres/SMTP/MCP/调度开关 |
| 图 | `app/graph.py` | 只建 `chatbot` + `ToolNode` + `tools_condition` |
| 工具 | `app/tools.py` | KB/媒体/记忆/邮件；`extra_tools` 接 MCP |
| 人设 | `app/prompts.py` | 个人超级助理；未点名小红书禁止 `search_kb` |
| MCP 服务 | `mcp_servers/personal.py` | FastMCP stdio：星期几、广州天气温度 |
| MCP 客户端 | `app/mcp_client.py` | `MultiServerMCPClient.get_tools()`；晨报用 `McpFactsProvider` |
| 记忆 | `app/postgres.py` | 缺库则创建；`PostgresSaver.setup()` + `PostgresStore.setup()` |
| 任务 | `app/jobs.py` | `run_morning_brief()` / `run_hydrate(slot)` / 启动补跑 |
| 调度 | `app/scheduler.py` | APScheduler Cron |
| 邮件 | `app/email_client.py` | SMTP_SSL |
| 合同 | `app/main.py` | 线程消息、resume、`POST /v1/assistant/jobs/run` |
| UI | `ui/streamlit_app.py` | 气泡、HITL 卡、pending 回显 |

`create_app(runtime=None)` 仍是工厂：导入 `app.main` 不会启动真实 embedding。测试注入 fake LLM、fake 媒体、hashing embed，并且 `scheduler_enabled=False`、`mcp_enabled=False`。

## 5. 图长什么样

**人话：** 整张图就两个房间。模型在 `chatbot` 里思考；一旦决定用工具，就进 `tools` 房间干活，干完再回 `chatbot` 说话。没有第三个「主管」房间。

### 5.1 只有两个节点

**人话：** 测试会断言节点集合里不能出现 Supervisor、review_media、天气节点之类的新名字。

```text
START
  └─ chatbot
        ├─ tools_condition == tools ─► tools ─► chatbot
        └─ tools_condition == END   ─► END
```

落地文件是 `app/graph.py`：

- `StateGraph(AgentState)`，状态 = `messages` + `last_image_path` + `last_video_path`
- `add_node("chatbot", RunnableCallable(chatbot, achatbot))`，同步 `invoke` 和异步 `ainvoke` 都能走
- `add_node("tools", ToolNode(tools, handle_tool_errors=False))`
- `add_conditional_edges("chatbot", tools_condition)`
- `add_edge("tools", "chatbot")`、`add_edge(START, "chatbot")`
- `compile(checkpointer=..., store=memory_store)`
- 绑工具时 `parallel_tool_calls=False`，并 `assert len(tool_calls) <= 1`，避免 HITL resume 时重跑媒体工具

MCP、邮件、记忆都只是 `tools` 列表里的新函数，**不新增节点**。

**对照文档：** [构建基础聊天机器人](https://langgraph.com.cn/tutorials/get-started/1-build-basic-chatbot/index.html)、[向聊天机器人添加工具](https://langgraph.com.cn/tutorials/get-started/2-add-tools/index.html)、[低层级概念](https://langgraph.com.cn/concepts/low_level.1.html)、[自定义状态](https://langgraph.com.cn/tutorials/get-started/5-customize-state/index.html)
### 5.2 一次调用怎么走

**人话：** 你发一句话，FastAPI 把它塞进 `ainvoke`。模型可以连续「想一想 → 调工具 → 再想」好几轮，直到它不再调用工具。

例子：用户说「今天广州多少度，发邮件告诉我」。

1. `POST /v1/threads/{id}/messages`
2. `graph.ainvoke({messages: [HumanMessage(...)]}, {configurable: {thread_id}})`
3. `chatbot` 给 LLM 看 `SYSTEM_PROMPT` + 历史消息 + 全部工具 schema
4. 模型可能先 `get_weather` → `tools` 执行 → 回 `chatbot`
5. 再 `send_email` → `tools` 执行 → 回 `chatbot`
6. 模型输出自然语言，`tools_condition` 走向 END
7. FastAPI 把气泡和可能的 HITL 卡序列化回 UI

媒体路径会在工具内部 `interrupt()` 停住，前端出现审核卡；`POST /v1/threads/{id}/resume` 用 `Command(resume=...)` 继续。

**对照文档：** [工具](https://langgraph.com.cn/agents/tools.1.html)、[添加人工介入](https://langgraph.com.cn/tutorials/get-started/4-human-in-the-loop/index.html)、[Human-in-the-loop 指南](https://langgraph.com.cn/agents/human-in-the-loop/index.html)

### 5.3 为什么不用 Supervisor / create_react_agent

**人话：** 官方文档里有「再请一个主管来分发任务」和「一行代码生成 ReAct 智能体」的做法。本项目故意不用，免得小红书、天气、邮件变成三套人设、三张图。

- 改造方案锁定「图节点仍只有 chatbot 和 tools」。
- 小红书只是能力，不是独立角色。
- `create_react_agent` 会把图拓扑藏进预置封装，后续 HITL、自定义状态、单工具串行更难对测试断言。
- MCP 中文文档示例常搭配 `create_react_agent` 或 streamable-http 天气服务，那是对照材料，不是本仓库实现。

**对照但不采用：** [多智能体系统概念](https://langgraph.com.cn/concepts/multi_agent.1.html)、[MCP](https://langgraph.com.cn/agents/mcp/index.html) 页中的预置智能体写法

## 6. 工具箱

**人话：** 助理的手只有一把，所有能力都挂在同一份 `tools` 列表上，最后交给同一个 `ToolNode`。

`app/tools.py` 的 `build_tools()` 组装顺序：

1. 本地工具：`search_kb`、`generate_image`、`generate_video`
2. 若有长期 store：`remember_fact`、`recall_facts`
3. 若有邮件客户端：`send_email`
4. 若有 `extra_tools`：MCP 转过来的 `get_current_datetime`、`get_weather`

**对照文档：** [向聊天机器人添加工具](https://langgraph.com.cn/tutorials/get-started/2-add-tools/index.html)、[工具（Tools）](https://langgraph.com.cn/agents/tools.1.html)

### 6.1 search_kb 实现了什么

**人话：** 它不是搜索全网，而是在本地讲义里做语义检索。只有你明确说「写小红书笔记」时，提示词才允许模型调用它。

例子：你说「帮我写敏感肌精华的小红书笔记」，模型应先 `search_kb(query=...)`；你只说「今天天气怎么样」，禁止调用。

**实现细节：**

- 工具层：`app/tools.py` 里 `@tool def search_kb(query, k=4)`，内部调用 `app/knowledge.py` 的 `search_kb(store, query, k)`。
- 索引层：启动时读取 `knowledge/*.md`，按 `##` 切段，超长再按约 800 字、重叠 80 切块，写入进程内 `InMemoryStore`，namespace `("kb",)`。
- 向量：生产用 SiliconFlow `BAAI/bge-m3`；测试用 hashing embed，不打真实 embedding。
- 命中过滤：`score <= 0` 丢掉；没有任何命中时返回字符串 `NO_HITS`。
- 返回给模型的是 `source=文件名` + 文本块，不是直接排版好的笔记。笔记结构【标题】【正文】【标签】由模型在看到检索结果后生成。
- 知识库不进 Postgres，重启 FastAPI 会重建索引。

**对照文档：** [工具](https://langgraph.com.cn/agents/tools.1.html)、[Memory / store 检索](https://langgraph.com.cn/agents/memory/index.html)、[Context](https://langgraph.com.cn/agents/context/index.html)
### 6.2 媒体 HITL

**人话：** 生图和生视频不是模型一开口就扣费，而是工具自己先举手问你「这段 prompt 和 cheapest 参数可以吗」。

实现仍在工具函数内部 `interrupt({type: review_media, tool, prompt, params})`，不新增 `review_media` 节点。Approve 后才调 Gateway/DashScope；Skip 只回一条 ToolMessage。自定义状态记下 `last_image_path` / `last_video_path`，UI 用 `st.image` / `st.video` 预览。

**对照文档：** [添加人工介入](https://langgraph.com.cn/tutorials/get-started/4-human-in-the-loop/index.html)、[HITL 指南](https://langgraph.com.cn/agents/human-in-the-loop/index.html)、[自定义状态](https://langgraph.com.cn/tutorials/get-started/5-customize-state/index.html)

### 6.3 长期记忆工具

**人话：** 「记住我周一交周报」不应只活在当前聊天泡泡里。换一个 `thread_id` 还应该能想起来。

- `remember_fact(fact)`：对文本做 sha256 截断当 key，`memory_store.put(("assistant", "profile"), key, {"text": fact})`
- `recall_facts(query)`：`memory_store.search(("assistant", "profile"), ...)`，没有则 `NO_FACTS`

生产写入 Postgres `store` 表；测试写入内存 store。

**对照文档：** [Memory](https://langgraph.com.cn/agents/memory/index.html)、[记忆分层概念](https://langgraph.com.cn/concepts/memory.1.html)、[Context](https://langgraph.com.cn/agents/context/index.html)

### 6.4 send_email

**人话：** 助理不能只在网页里说话。晨报和「把这段发我邮箱」都要能寄出 163 邮件。

`send_email(subject, body)` 调 `SmtpEmailClient.send()`：`SMTP_SSL smtp.163.com:465`，收件人来自 `SMTP_TO`。密钥只在 `.env`。工具成功时返回 JSON `{ok, subject, to}`，不把授权码回给模型。

**对照文档：** [工具](https://langgraph.com.cn/agents/tools.1.html)（自定义副作用工具）

### 6.5 MCP 工具

**人话：** 星期几和天气不是写死在 Python if-else 里的「星期四就带伞」，而是两个外部工具，模型和晨报任务都可以用。

并入 ToolNode 后的名字是 `get_current_datetime`、`get_weather`。下一节把调度过程拆开讲。

**对照文档：** [MCP](https://langgraph.com.cn/agents/mcp/index.html)、[MCP API](https://langgraph.com.cn/reference/mcp/index.html)

## 7. MCP：两层实现与一次完整调度

**人话：** MCP 可以想成「插头规范」。`mcp_servers` 是墙上的插座，真正去看表、查天气；`mcp_client` 是插头，把插座变成 LangChain 工具，插进现有工具箱。图本身不知道 MCP 的存在，它只看见普通工具。

### 7.1 FastMCP 和 MCP 有什么区别

**人话：** MCP 是协议，FastMCP 是写这个协议服务端的快捷库。不是两种互抢的产品。

| 名字 | 它是什么 | 在本项目里的位置 |
| --- | --- | --- |
| MCP | Model Context Protocol，规定客户端如何发现/调用工具 | 传输层约定；本仓库用 **stdio**，不用 streamable-http |
| FastMCP | Python MCP 服务端的高层封装，`mcp.server.fastmcp.FastMCP` | `mcp_servers/personal.py` 用 `@mcp.tool()` 暴露两个函数 |
| langchain-mcp-adapters | 把 MCP 工具转成 LangChain Tool 的客户端适配器 | `app/mcp_client.py` 的 `MultiServerMCPClient` |

官方 MCP 页常示范 `create_react_agent` + 远程天气 HTTP。本仓库对照该页的「工具可被智能体调用」这一点，但实现改成：仓库内 FastMCP stdio + 现有 `ToolNode`。

**对照文档：** [MCP](https://langgraph.com.cn/agents/mcp/index.html)、[MCP API 参考](https://langgraph.com.cn/reference/mcp/index.html)
### 7.2 mcp_servers 做了什么（服务端层）

**人话：** 这一层不聊天、不发邮件，只回答两个事实问题：现在星期几、某座城市现在什么天气。

`mcp_servers/personal.py`：

- `FastMCP("personal")`
- `get_current_datetime()`：`Asia/Shanghai` 的 iso/date/time/weekday
- `get_weather(city="广州")`：广州有内置坐标；其他城市走 Open-Meteo geocoding；天气走 `api.open-meteo.com`，无 API key
- WMO 天气代码映射成「小雨」「晴」等中文
- `__main__` 里 `mcp.run(transport="stdio")`，作为子进程被拉起

它运行在独立 Python 进程里，通过标准输入输出和父进程说话，不进入 LangGraph 节点列表。

### 7.3 mcp_client 做了什么（应用适配层）

**人话：** 这一层负责「把插座变成模型能调用的函数」，以及晨报那种「不等模型想，直接把事实取来」。

`app/mcp_client.py` 做四件事：

1. `aload_mcp_tools()`：构造 `MultiServerMCPClient({"personal": {transport: stdio, command: 当前解释器, args: [mcp_servers/personal.py]}})`，然后 `get_tools()`。
2. 生产 `build_runtime()` 在 `mcp_enabled=True` 时把这些工具当作 `extra_tools` 传给 `build_tools()`。
3. `McpFactsProvider`：按名字找到 `get_current_datetime` / `get_weather`，直接 `ainvoke`，拼成 `DayFacts(weekday, weather, temperature_c, city, ...)`。
4. 测试用 `StaticFactsProvider` + fake tools，不拉真实子进程、不打 Open-Meteo。

所以：

- 聊天路径把 MCP 工具交给 LLM 选择（软调度）
- 晨报路径由 jobs 代码指定调用哪两个工具（硬调度）
### 7.4 前端问「今天星期几」，是否也能调度工具？

**人话：** 能。你不需要等 08:00，也不需要点「运行任务」。只要这句话让模型认为该查日期，它就会走和写稿、发邮件同一条工具回路。

这叫软调度：调度者是 chatbot 里的 LLM，不是 APScheduler。

前提：

- 生产 `mcp_enabled=True`，启动时已经 `load_mcp_tools()`
- `SYSTEM_PROMPT` 写明：需要了解今天星期几或当前时间时调用 `get_current_datetime`
- 图上 `ToolNode` 已包含该工具

测试里 `tests/test_mcp_personal.py` 会断言绑定工具名包含 `get_current_datetime` 和 `get_weather`，同时图节点仍然只有 `chatbot` 和 `tools`。

注意：默认 pytest 为了全 mock，会设 `mcp_enabled=False` 并注入 fake 工具。那只影响测试进程，不影响你本地 uvicorn 生产启动。

### 7.5 晨报如何硬调度 MCP

**人话：** 晨报不能赌模型「想不想起查天气」。代码先把星期几/天气/温度查实，再把这些事实写进提示词，命令同一张图必须 `send_email`。

`run_morning_brief()` 的顺序：

1. 看长期 store 里今天的 `morning_brief:YYYY-MM-DD` 是否已做（幂等）
2. `facts_provider.aget_facts(assistant_city)` → 真实 MCP
3. `graph.ainvoke(晨报提示词, thread_id=assistant-morning-brief-日期)`，超时 180 秒
4. 若模型已经调用 `send_email`，记 `status=sent`
5. 若超时或没发出，jobs 自己 SMTP 发事实摘要，记 `status=sent_fallback`

硬调度发生在第 2 步，根本不经过 `tools_condition`。第 3 步才进入图，那时 MCP 事实已经在用户消息里了。
### 7.6 信息怎么流通（一个完整例子）

**人话：** 下面把「你在网页里问今天星期几」从左走到右写一遍。每一跳都在不同层。

```text
1. UI 层
用户在 Streamlit 输入「今天星期几」
    -> POST /v1/threads/{thread_id}/messages

2. 合同层  app/main.py
create_app 收到消息
    -> runtime.graph.ainvoke({messages: [HumanMessage("今天星期几")]})

3. 图层  app/graph.py
chatbot 把 SYSTEM_PROMPT + 历史 + 工具 schema 交给 ChatOpenAI
    -> 模型返回 tool_call: get_current_datetime
    -> tools_condition 把控制权交给 tools 节点

4. 工具节点层  LangGraph ToolNode
ToolNode 按名字找到 LangChain 工具 get_current_datetime
    -> 这不是本地 @tool，而是 mcp_client 从 MCP 适配来的

5. 客户端适配层  app/mcp_client.py
MultiServerMCPClient 通过 stdio JSON-RPC 把 call_tool 发给子进程

6. 服务端层  mcp_servers/personal.py
FastMCP 执行 get_current_datetime()
    -> 读取 Asia/Shanghai 本地时钟
    -> 返回 {iso, date, time, weekday: "星期四", timezone}

7. 回到图
ToolMessage 进入 messages
    -> 回到 chatbot
    -> 模型用自然语言说「今天是星期四」
    -> tools_condition -> END

8. 回到 UI
FastAPI 序列化气泡，Streamlit 画出来
```

晨报例子只在第 2 步之前多一刀：`jobs.py` 先走 5/6 拿到 `DayFacts`，再把事实写进 HumanMessage，然后从 3 开始。聊天软调度和晨报硬调度共用 5/6 的同一对 MCP 工具，只是谁先开口不同。

**对照文档：** [MCP](https://langgraph.com.cn/agents/mcp/index.html)、[添加工具](https://langgraph.com.cn/tutorials/get-started/2-add-tools/index.html)、[智能体概念](https://langgraph.com.cn/concepts/agentic_concepts.1.html)

## 8. 长期记忆如何实现，数据库表分别是什么意思

**人话：** 这个项目把「记得」分成三格抽屉，不要混：当前这轮对话、跨对话的个人事实、写小红书用的讲义。只有前两格进 Postgres。

可以把它想成：聊天记录是草稿纸（checkpoint），「我对花生过敏」是通讯录（store），小红书运营手册是桌上那本不会入库的讲义（KB）。

**对照文档：** [添加记忆](https://langgraph.com.cn/tutorials/get-started/3-add-memory/index.html)、[记忆分层](https://langgraph.com.cn/concepts/memory.1.html)、[Memory](https://langgraph.com.cn/agents/memory/index.html)、[持久化概念](https://langgraph.com.cn/concepts/persistence.1.html)、[Postgres 接法](https://langgraph.com.cn/how-tos/persistence.1.html)、[Context](https://langgraph.com.cn/agents/context/index.html)

### 8.1 短期记忆：当前线程聊到哪了

**人话：** 同一条 `thread_id` 刷新后还能续聊，是因为每次 `ainvoke` 都把图状态 checkpoint 下来。换一条线程就是另一本草稿纸。

- 生产：`PostgresSaver`（`app/postgres.py` 的 `AppPostgresSaver`，给 sync API 补了 `aget_tuple` 等异步方法，否则 `ainvoke` 会卡住）
- 测试：`InMemorySaver`，不连真实 Postgres
- 键：`{"configurable": {"thread_id": ...}}`
- 晨报也有自己的 thread：`assistant-morning-brief-YYYY-MM-DD`，避免和你的聊天泡泡混在一起

### 8.2 长期记忆：跨线程的事实和任务幂等

**人话：** 「记住我加班到很晚」应该明天另一个会话还能召回；「今天晨报发过了」也不该因为重启 FastAPI 再发一封。

- 生产：`PostgresStore`；测试：内存 `InMemoryStore`
- 个人事实 namespace：`("assistant", "profile")`，工具是 `remember_fact` / `recall_facts`
- 任务幂等 namespace：`("assistant", "jobs")`，key 例如 `morning_brief:2026-09-17`、`hydrate:2026-09-17:10`
- live 验收时，store 里出现过 `assistant.jobs` / `morning_brief:2026-09-17` / `status=sent`

`compile(..., store=memory_store)` 让工具能拿到这颗跨线程 store。密钥不进 store。
### 8.3 知识库：第三块，而且故意不进 Postgres

**人话：** 小红书讲义是给 `search_kb` 用的，不是给你的个人档案用的。它继续住在进程内 `InMemoryStore`，用 embedding 做语义检索。

改造方案明确：不用 pgvector，不把 KB 迁进 Postgres。所以 `store_vectors` 这类向量表本项目不启用。

### 8.4 数据库表分别有什么含义

**人话：** 打开 Postgres，你会看到两摊表。一摊像「对话录像带」，一摊像「钥匙柜」。不要把它们理解成业务里手写的 user/order 表。

`PostgresSaver.setup()` 建短期记忆表：

| 表 | 一句话 | 里面有什么 |
| --- | --- | --- |
| `checkpoint_migrations` | 记忆库自己的升级记录 | 版本号 `v`，保证 `setup()` 可重复执行 |
| `checkpoints` | 每个快照的目录页 | `thread_id`、`checkpoint_id`、父快照、checkpoint JSON、metadata |
| `checkpoint_blobs` | 快照里每个通道的大对象 | 例如 `messages`、`last_image_path` 的序列化 blob 与 version |
| `checkpoint_writes` | 某个节点刚写待提交的增量 | HITL `interrupt()` / resume 时尤其需要，避免把半成品丢掉 |

`PostgresStore.setup()` 建长期记忆表：

| 表 | 一句话 | 里面有什么 |
| --- | --- | --- |
| `store` | 跨线程 KV | `prefix`（namespace，如 `assistant.profile`、`assistant.jobs`）、`key`、`value` JSONB、时间戳、可选 TTL |
| `store_migrations` | store schema 升级记录 | 与 checkpoint_migrations 同理 |
| `store_vectors` | 库可选的向量索引表 | 本项目不启用。KB 不用 pgvector |

业务数据怎么躺在 `store` 里：

| prefix | key 例子 | value 含义 |
| --- | --- | --- |
| `assistant.profile` | 事实文本的短哈希 | `{"text": "对花生过敏"}` |
| `assistant.jobs` | `morning_brief:2026-09-17` | `{"status": "sent", "date": "2026-09-17"}` |
| `assistant.jobs` | `hydrate:2026-09-17:10` | 该时段喝水邮件已发送 |

没有单独的 `users`、`emails`、`weather` 业务表。天气是现查的，邮件只经 SMTP 发出，不落库。

## 9. 定时任务是怎么实现的

**人话：** 不是 LangGraph 云平台的 Cron，也不是 Windows 计划任务。FastAPI 进程活着时，APScheduler 在进程里对着 Asia/Shanghai 的钟点喊 `run_morning_brief()` / `run_hydrate(slot)`。

可以把它想成后厨墙上的闹钟：闹钟响了就按同一张菜单炒菜（晨报走图），倒水（喝水不走模型）。闹钟停在 FastAPI 进程里，进程挂了闹钟也停。

### 9.1 为什么不用 Platform Cron

**人话：** 中文 FAQ 里的 Cron 属于 LangGraph Platform。本仓库是本地 OSS + uvicorn，没有那套托管调度，所以自己挂 APScheduler。

**对照但不采用：** [FAQ](https://langgraph.com.cn/concepts/faq/index.html)

### 9.2 APScheduler 挂在哪

**人话：** 只有生产 FastAPI 启动、且 `SCHEDULER_ENABLED=true` 时才上钟。pytest 默认关掉，避免测试时真的到点发信。

`app/main.py` 的 lifespan：

1. `start_scheduler(runtime)`
2. `acatch_up_jobs(runtime)`：若现在已经过了 08:00，补跑今天晨报；若当前小时正好是喝水点，只补当前点，不把下午的提前发掉；22:00 之后不再补跑

`app/scheduler.py`：

- 08:00 `run_morning_brief`
- 10/12/14/16/18/20/22 `run_hydrate`
- `BackgroundScheduler(timezone=ASSISTANT_TIMEZONE)`
### 9.3 晨报和喝水两条线

**人话：** 晨报要「看天说话」，所以走模型和 MCP；喝水只需要报时，所以不浪费 token。

晨报 `run_morning_brief()`：

1. MCP 硬取 `DayFacts`
2. 同一张图 `ainvoke`，要求调用 `send_email`，subject「晨间简报 YYYY-MM-DD」
3. 正文先陈述星期/天气/温度，再给 2-4 条临场建议，禁止套小红书格式
4. 08:00 喝水提醒并进晨报正文
5. 图调用超过 180 秒则 fallback：仍发事实邮件
6. ChatOpenAI 还有 `timeout=90`、`max_tokens=1024`，避免网关无限生成

喝水 `run_hydrate(slot)`：

- `slot=08` 直接返回 `merged_into_morning_brief`，不再发第二封
- 其他点发固定正文「现在是 10:00，记得喝一杯水。」
- 不调用 LLM，不调用 MCP

幂等：同一天同一 key 已在 `assistant.jobs` 就 `skipped`。手动验收可 `force=True`。

### 9.4 立刻跑、不等 08:00

**人话：** 交付不能坐等到明天早上。函数和 HTTP 都可以马上跑晨报。

- Python：`run_morning_brief(runtime, force=True)`
- HTTP：`POST /v1/assistant/jobs/run`，body `{"kind":"morning_brief","force":true}`
- live 门禁：`RUN_LIVE_ASSISTANT=1` 跑 `tests/test_live_assistant.py`，忽略墙上时钟

**对照文档：** 图执行仍是 [基础聊天机器人](https://langgraph.com.cn/tutorials/get-started/1-build-basic-chatbot/index.html) + [工具](https://langgraph.com.cn/tutorials/get-started/2-add-tools/index.html)；调度本身不是 LangGraph 节点。

## 10. FastAPI 合同

**人话：** 网页和定时任务都打同一扇门。聊天走线程接口，闹钟走 jobs 接口，媒体预览仍是只读文件接口。

无鉴权，本地 CORS 默认允许 Streamlit。消息/resume 已从 `invoke` 改为 `ainvoke`。

| 方法 | 路径 | 含义 |
| --- | --- | --- |
| GET | `/health` | `{status: ok}` |
| GET | `/v1/config` | 公开 cheapest 配置，不含密钥 |
| POST | `/v1/threads` | 创建 `thread_id` |
| GET | `/v1/threads/{id}` | 气泡 + 可能的 `review_media` interrupt |
| POST | `/v1/threads/{id}/messages` | 发用户消息；interrupted 时 409 |
| POST | `/v1/threads/{id}/resume` | `{action, prompt, params}`；非 interrupted 时 409 |
| POST | `/v1/assistant/jobs/run` | `kind=morning_brief` 或 `hydrate`，hydrate 要带 `slot` |
| GET | `/v1/media/{images|videos}/{file}` | 只读子目录，防 `..` 逃逸 |

jobs body 例子：

```json
{"kind": "morning_brief", "force": true}
{"kind": "hydrate", "slot": "10"}
```

改 `.env` 里的模型名仍须重启 uvicorn。`Settings` 启动时读一次。

**对照文档：** [HITL](https://langgraph.com.cn/agents/human-in-the-loop/index.html)（resume 对应 `Command(resume=...)`）、[低层级 Command](https://langgraph.com.cn/concepts/low_level.1.html)

## 13. 已修问题与开放风险

**人话：** mock 绿了不等于网关就快。晨报曾经像「卡住」，其实是聊天模型在网关里生成太久。

### 已关闭

**人话：** 下面这些问题已经修过，不要再当成当前故障。

- 导入 `app.main` 曾在 pytest 触发真实 embedding。改为纯工厂。
- Streamlit 发送后用户气泡消失。用 `pending_user` 立即回显。
- 生产 `PostgresSaver` 缺异步方法，`ainvoke` 无法在事件循环里读 checkpoint。补了 `ThreadedAsyncCheckpointMixin`。
- Windows 下缺库时报错乱码，无法判断要不要 `CREATE DATABASE`。改为查 `pg_database`。
- live `graph.ainvoke` 像挂死：网关无 `max_tokens` 时可能超过 20 秒甚至顶满 90 秒。现为 ChatOpenAI 设 `timeout=90`、`max_tokens=1024`；晨报再包 180 秒，超时仍 SMTP fallback。

### 仍开放

**人话：** 下面这些不是没做完的功能，而是已知风险，交付后仍要盯。

- 网关对短 ping 也可能超过 20 秒；晨报可能走到 `sent_fallback`。这仍算发出邮件，但建议不是模型临场写的。
- live 媒体（DashScope/Gateway）仍是可选冒烟，费用和网络会独立失败。
- hashing embed 只用于测试；线上检索质量取决于 bge-m3。
- KB 索引不落盘，重启 FastAPI 会重建；embedding 失败则启动失败。
- Streamlit 重启后 UI 会话丢失，不会自动列出旧 `thread_id`。
- 当前非流式；HITL 期间必须停住。
- langgraph.com.cn 镜像可能落后或改路径，学习链接需定期复核。
- APScheduler 跟 FastAPI 进程走，进程挂了闹钟就停；这是本地 OSS 的取舍，不是平台 Cron。

## 14. 启动与提交纪律

**人话：** 本地永远起两个进程；密钥永远只呆在 `.env`。

```powershell
.\venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
.\venv\Scripts\python.exe -m streamlit run ui/streamlit_app.py
.\venv\Scripts\python.exe -m pytest
```

```powershell
# POST http://127.0.0.1:8000/v1/assistant/jobs/run
```
