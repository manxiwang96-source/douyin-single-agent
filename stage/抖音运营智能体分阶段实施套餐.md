## 1. 当前仓库事实（未改工人代码前）

- 现网仍是个人超级助理：FastAPI + Streamlit + LangGraph `START -> chatbot -> tools_condition -> tools -> chatbot`。
- 记忆 namespace 仍是全局 `("assistant", "profile")` / `("assistant", "jobs")`；知识库是进程内 `("kb",)` + 小红书 `knowledge/*.md`。
- `POST /v1/threads` 无 `user_id` / `agent_instance_id`；`app.state.threads` 是内存 set。
- 媒体 URL 仍是 `/v1/media/{kind}/{file_name}`，目录未按用户/实例隔离。
- `app/config.py` 尚未加载 Dify 字段（`extra="ignore"`）。`.env.example` 已有 `DIFY_BASE_URL` / `DIFY_API_KEY` / `DIFY_LEAD_APP_ID` / `DOUYIN_HTTP_*`。
- 本地 `.env` 已有 Dify Service API Key 和 `DIFY_BASE_URL`（用户确认 C 的工作流已发布且控制台跑通）。`DOUYIN_HTTP_BASE_URL` / `DOUYIN_HTTP_API_TOKEN` 可空，C 的工作流内有默认值。不要把真实值抄进文档。
- 没有 `knowledge/douyin_ops_demo/`，没有登录/广场/DifyClient。
- 脏文件 `docs/summary/个人超级助手总结与逻辑复盘（2）.md` 不要碰。既有 `test_assistant_summary_doc.py` 失败不纳入本改造。

## 2. 全程锁定（所有阶段都遵守）

- 本仓库是单个工人，不是主管，不是 C 的 Dify。禁止改 C 的工作流。不要改 C 的工作流。
- 图节点只保留 `chatbot` 和 `tools`。禁止 `create_react_agent`、工人内部 Supervisor、Dify 专用节点、把 Dify 包成 MCP。
- v1 只有一个产品工具 `discover_douyin_leads` → `POST {DIFY_BASE_URL}/workflows/run`，请求头 `Authorization: Bearer {DIFY_API_KEY}`。`no_send=false` 由代码写死，不是环境变量。
- 不再采用：`difyctl`、`DIFYCTL_BIN`、`DIFY_COMMENT_APP_ID`、`DIFY_DM_APP_ID`、`reply_douyin_comment`、`send_douyin_dm`、通用工具 `run_dify_workflow`。
- 一人多实例；v1 模板只有 `douyin_ops`；能力只展示、不勾选；点进对话不更新 `agent_instances.updated_at`。
- Store namespace：`(user_id, agent_instance_id, "profile"|"kb")`。生产 Postgres 是真相源。禁止 ALTER LangGraph 官方表，禁止生产默认 SQLite。
- Streamlit 是 v1 过渡客户端；HTTP 契约必须让后续前端直接接（`Authorization: Bearer <session>` + JSON）。不要发明 Streamlit 专用字段。
- 真实登录：`login_name` + 密码哈希。默认关闭 08:00 晨报/喝水 APScheduler；对话里保留 `send_email`、天气 MCP、`remember_fact` / `recall_facts`。
- 阶段 0–6：`DIFY_LIVE_ENABLED` 默认 false，测试只注入 FakeDifyClient。阶段 7 才允许真发。
- 生图/生视频继续 `interrupt()`；评论/私信 v1 不审、不做待审 API。
- 抖音 8 点扫描发送本套餐不实现（表和取消规则要建好）。

## 4. 阶段 1 — 业务表与仓库

### 目标

### 表（字段以设计方案第 11 节为准）

## 5. 阶段 2 — 登录与广场 API

### 目标
后续前端只靠这一套 HTTP 就能登录、建卡、进对话。Streamlit 本阶段可以先不改。

### 鉴权
- 密码：标准库 PBKDF2-SHA256，格式 `pbkdf2_sha256$iterations$salt$hash`，不存明文。
- `POST /v1/auth/register` `{login_name, password}`：login_name 唯一；密码至少 8 位；409 重复。
- `POST /v1/auth/login` → `{token, user_id, login_name}`；session 7 天；禁用用户 403。
- `POST /v1/auth/logout`、`GET /v1/me`。
- 除 `/health`、`/v1/config`、`/v1/auth/*` 外，业务接口要 `Authorization: Bearer <token>`。
- 旧的未登录 `POST /v1/threads` 不再当产品入口；相关测试改为先注册登录。

### 广场
- `GET /v1/agent-instances`：当前用户未归档卡片（头像、名称、简介、模式、created_at、updated_at）。
- `POST /v1/agent-instances`：v1 只接受 `template_code=douyin_ops` + `title` + `intro` + 可选头像。创建时：INSERT 实例、绑定 `douyin-lead-discovery`、seed `knowledge/douyin_ops_demo`。创建动作不把 seed 当成卡片编辑。
- `PATCH /v1/agent-instances/{id}`：只改 title/intro/avatar 才更新 `updated_at`。
- `POST /v1/agent-instances/{id}/open`：复用该实例最近 `status=active` 的 `app_threads`，没有则 INSERT。此接口不得更新卡片 `updated_at`。
- `GET /v1/agent-instances/{id}/sidebar`：应用描述与开发要点来自目录；模式只读 `single`；知识库来自 `agent_knowledge_documents`；工作流/工具名称来自目录 × 绑定。不要读 `workflow_runs`。无模型栏。能力不可勾选。
- 头像持久目录，不进 `media_assets`，不走 7 天过期。

### 不做
- 不改图检索，不调 Dify，不实现完整 Streamlit 广场（阶段 6）。

### 验证
- 未登录 401；一人多实例；空白/重名 title 4xx；点开对话后 `updated_at` 不变；创建后必有绑定和 demo 文档；侧边栏不泄漏 `DIFY_API_KEY`。

### 提交
中文：`实现登录与智能体广场 HTTP 契约`。

## 7. 阶段 4 — Dify 工具（mock）

### 目标
对话能走通「要评论/私信 → 工具 → 记账 → 回写」，但不打真实 Dify。

### DifyClient
- `run(name, inputs) -> {ok, name, workflow_run_id, status, outputs, error}`
- `POST {DIFY_BASE_URL}/workflows/run`，Bearer `DIFY_API_KEY`，`response_mode=blocking`，超时 `DIFY_TIMEOUT_S`。
- 用 httpx（线程或 async），禁止无限阻塞事件循环。
- HTTP 401 / 密钥无效 → `auth_expired`。超时单独分类。
- `DIFY_LIVE_ENABLED=false` 时生产路径不得发网（测试永远注入 Fake）。

### 工具 `discover_douyin_leads`
- 进现有 ToolNode。未绑定 `douyin-lead-discovery` 则拒绝。
- 模型可填：`account`（自由文本，必填）、`keyword` 或 `video_id`、`limit`、`channels`、`list_status`。
- 服务器填：`no_send=false`、`auto_login=true`；`base_url`/`api_token` 仅当 `.env` 非空才写入 inputs，空则省略，走 C 工作流默认值。
- `user` 字段用我们的 `user_id`。
- `douyin_accounts` 若已有该账号且状态 `paused`/`needs_login` 则拒调；无投影行时仍允许模型传入的 `account`。v1 不做账号白名单。
- 短窗口（10 分钟）相同 `user_id + agent_instance_id + account + keyword + video_id` 若已有进行中 run，不得二次 POST。

### 回写
- 每次调用一行 `workflow_runs`，inputs/outputs 整份 JSONB。
- 尽力解析 `list_comment` / `list_message` / `snapshot` 写入 `engage_*`；形状不明时工具仍成功，对话汇报原文摘要，不阻塞闭环。
- v1 多数行直接落到 `sent` / `failed` / `needs_login`。不做待审 API。
- 提示词必须让模型对用户说「会真实发送」，不要说先出草稿。

### 不做
- 不启用 live。不实现 8 点 APScheduler。不拆两个发送工具。

### 验证
- 全部 mock HTTP。绑定缺失拒调；live 关闭不发网；重入不二次 POST；401→`auth_expired`；发给 client 的 inputs 里 `no_send` 恒为 false；不明输出仍落 `workflow_runs`。
- 默认 pytest 不出现真实 Dify 地址请求。

### 提交
中文：`接入线索发现工具并 mock 回写触达结果`。

## 8. 阶段 5 — 任务取消

### 目标

### 验证
