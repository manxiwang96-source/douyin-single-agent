## 2. 当前事实（不要重做）

后端已经够用，Vue 直接接 Bearer JSON。错误体为 `{"detail":"..."}`。

- `GET /v1/agent-instances`：当前用户 `status <> archived` 的卡片。
- `POST /v1/agent-instances`：v1 只接受 `template_code=douyin_ops`。
- `PATCH /v1/agent-instances/{id}`：可选 `title` / `intro` / `avatar`。只改这些字段才更新 `updated_at`。未登录 401；不存在/他人/已归档/非法 UUID 404；名称冲突 409 `title already in use`。
- `DELETE /v1/agent-instances/{id}`：HTTP 层 `_owned_instance` 后调用现有 `archive_agent_instance`。成功 200 `{"ok": true, "agent_instance_id": "<uuid>", "status": "archived"}`。未登录 401 `not authenticated`。不存在/他人/已归档/非法 UUID 404 `agent instance not found`。二次 DELETE 也是 404。
- 归档后列表不再返回该卡；`open` / `sidebar` / `patch` / 再 `DELETE` 均为 404；同名可再建。
- 后端 `AgentInstancePatchIn.avatar` 缺省 `None`。`main.py` 仅当 `body.avatar is not None` 才存新头像，否则 `UNSET`（保留）。因此 JSON 省略 `avatar` 或显式 `null` 都不会改头像，**不能清空头像**。
- 前端已有：`listAgentInstances` / `createAgentInstance` / `openAgentInstance` / `getAgentSidebar`；`validateTitle` / `validateIntro`；`apiErrorMessage` 已把 `title already in use` 映射成「名称已被使用」。
- `AgentCard.vue` 整卡仍是单个 `<button>`，点击即 `open`。`PlazaView.vue` 只有新建弹窗。`CreateAgentModal.vue` 只服务新建，打开必从模板步开始。
- 对话页 `ChatView` + 只读侧边栏已闭环，本窗口不改。

## 3. 锁定决策

- **只做广场**：改（名称/简介/头像）+ 删（归档）。对话页不改，不在聊天顶栏放编辑/归档。
- 卡片主体仍进对话；底部「编辑」「归档」必须 `stopPropagation`，避免点按钮也 `open`。
- 整卡不要再是单个 `<button>`：底栏再放按钮会变成非法嵌套。改成卡片容器，主体可点进对话，底栏独立按钮。
- 编辑复用 `CreateAgentModal` 资料步，**跳过模板**。不要新做第三个资料表单。校验与新建相同：名称去首尾空白后非空、不能含空白、最多 30；简介非空、最多 150。
- 编辑弹窗标题用「编辑智能体」，提交按钮用「保存」。打开时预填当前卡片的名称、简介、头像预览。
- `PATCH` 始终带 `title` / `intro`；**只有新选图片才带 `avatar`**（省略=保留）。不要传空字符串头像，不要试图清空头像。
- 归档：自定义二次确认 → `DELETE`（`status=archived`）→ 刷新列表。不要 `window.confirm`，不要引入 Element Plus / Naive UI / Ant Design Vue。
- 409 `title already in use` → 「名称已被使用」。未登录 401 走现有错误映射。归档 404 显示用户能看懂的失败文案后刷新列表。
- 不做：恢复归档、硬删除、对话页改删、任务取消、改 FastAPI / Dify / Streamlit / C 的工作流。
- CSS 前缀继续 `agent-`，scoped。标识符英文。
- 本窗口覆盖旧 Vue 套餐「v1 界面不要做改名 PATCH」这一句，但不要去改那份旧文档。

## 4. 页面与交互

### 4.1 卡片 `AgentCard.vue`

- 主体（头像、名称、简介、模式、时间）点击仍 `emit('click', id)`，广场继续 `open`。
- 底栏两个按钮：「编辑」「归档」，点击 `stopPropagation` 后分别 `emit('edit')` / `emit('archive')`。
- 不要把编辑/归档做成整卡 hover 才出现的唯一入口；底栏始终可见即可。
- 头像仍走现有 Bearer blob 预览。

### 4.2 编辑弹窗（复用 `CreateAgentModal.vue`）

- 新建：行为保持两步（模板 → 资料），payload 仍锁 `douyin_ops`。
- 编辑：打开直接资料步，跳过模板；不提交 `template_code`；调用 `PATCH`。
- 预填 `title` / `intro`；已有头像只做预览，不把旧 base64 回传。
- 用户新选图片后才把 `avatar` 放进 PATCH body。
- 成功关闭弹窗并让广场 `GET` 刷新。取消/点遮罩关闭不发请求。

### 4.3 归档二次确认

- 可在 `PlazaView.vue` 加轻量确认弹窗，或抽一个小确认组件。文案说清：归档后广场不再展示，对话入口失效，同名以后可再建；不是物理删除。
- 确认后 `DELETE /v1/agent-instances/{id}`；取消关闭确认框，列表不变。
- 成功后刷新列表，该卡消失。不要做恢复入口。

### 4.4 对话页

不改。不把审核卡、头像气泡、侧边栏纳入本窗口。

## 5. 一次交付的施工顺序

一次完整交付。下面步骤只是本窗口内部顺序，不是要开多个对话。

### 步骤 1 — API 客户端

改 `frontend/src/api/agents.ts`：

- `patchAgentInstance(id, { title, intro, avatar? })` → `PATCH /v1/agent-instances/{id}`
- `archiveAgentInstance(id)` → `DELETE /v1/agent-instances/{id}`
- PATCH body 用普通对象组装：始终有 `title`、`intro`；仅当传入新 `avatar` 字符串时才加该键。不要 `avatar: null`。

### 步骤 2 — 卡片底栏

改 `frontend/src/components/AgentCard.vue`：去掉整卡 `<button>`，主体点击进对话，底栏「编辑」「归档」`stopPropagation`。

### 步骤 3 — 弹窗复用与广场接线

改 `frontend/src/components/CreateAgentModal.vue`、`frontend/src/views/PlazaView.vue`：

- 弹窗增加编辑模式（跳过模板、预填、PATCH）。
- 广场接收 `edit` / `archive`；编辑打开弹窗；归档打开二次确认。
- 成功后 `loadCards()`。

### 步骤 4 — Vitest 与 build

补/改 `frontend/tests/`（优先 `plaza.test.ts`、`components.test.ts`，必要时加卡片测试）：

- 创建 payload 仍锁 `douyin_ops`。
- 编辑模式打开即资料步，文案含「编辑智能体」，不含模板卡「抖音运营助手」作为可点模板（或至少不会再走新建两步）。
- PATCH 未新选图片时 keys 只有 `title`、`intro`。
- 新选图片时才含 `avatar`。
- 点「编辑」「归档」不触发卡片 `click`/`open`。
- 归档确认后调用 DELETE；取消不调用。
- 409 仍显示「名称已被使用」。

然后：

```powershell
cd frontend
npm test
npm run build
```
